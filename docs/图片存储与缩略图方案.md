# 图片存储与缩略图生成方案

> 版本：v1.0（定稿）
> 适用：个人信息管家 · 图片/附件存储
> 状态：待实现

---

## 〇、规格定稿

| 项 | 规格 |
|---|---|
| 图片大小 | 单张 **≤ 10 MB**（超限拒绝） |
| 格式 | JPEG / PNG / WebP（双端校验） |
| 原图 | 保留，不压缩画质 |
| 缩略图 | 自动生成 **128 / 256 / 512** 三档 |
| 文件重名 | 允许，**不建唯一约束** |
| 文件名 | 1–20 字符，仅中英文、数字、下划线；修改/上传**无频率限制** |
| 主键 ID | `BIGINT` 自增，展示零填充为 9 位数字（`000000001`） |

---

## 一、数据表：`images`

| 字段名 | 类型 | 长度 | 可空 | 默认值 | 索引 |
|---|---|---|---|---|---|
| `id` | `BIGINT` | — | 否 | 自增 | `PRIMARY KEY` |
| `owner_id` | `uuid` | — | 否 | — | 普通索引（RLS 隔离，关联 `auth.uid()`） |
| `name` | `VARCHAR` | 20（字符） | 否 | — | 无（允许重名） |
| `mime_type` | `VARCHAR` | 32 | 否 | — | 无 |
| `size` | `BIGINT` | — | 否 | — | 无（原图字节数） |
| `original_path` | `TEXT` | — | 否 | — | 无（原图 object key） |
| `thumb_128_path` | `TEXT` | — | 是 | `NULL` | 无 |
| `thumb_256_path` | `TEXT` | — | 是 | `NULL` | 无 |
| `thumb_512_path` | `TEXT` | — | 是 | `NULL` | 无 |
| `created_at` | `TIMESTAMPTZ` | — | 否 | `now()` | 无 |
| `updated_at` | `TIMESTAMPTZ` | — | 否 | `now()` | 无 |

> 二进制不落数据库，仅存对象存储 object key；展示时经 CDN / `getSignedUrl` 生成访问地址。

## 二、对象存储目录结构

object key 由**全局唯一自增 id** 生成，天然规避重名冲突：

```
images/{owner_id}/{id:09d}/original.{ext}
images/{owner_id}/{id:09d}/thumb_128.{ext}
images/{owner_id}/{id:09d}/thumb_256.{ext}
images/{owner_id}/{id:09d}/thumb_512.{ext}
```

- `{owner_id}`：用户隔离与批量清理；
- `{id:09d}`：零填充 9 位 ID（`000000001`）；
- `{ext}`：`jpg` / `png` / `webp`（由真实格式决定，不信任上传扩展名）。

## 三、上传与缩略图生成流程

```
客户端选图
  └─ 前端预检：格式(扩展名+MIME) + ≤10MB
       ├─ 不通过 → 拒绝并提示
       └─ 通过 → 上传原图到对象存储
            └─ 服务端分配 id（BIGINT 自增）
                 └─ 图像处理库生成 128/256/512 三档缩略图
                      └─ 上传三档缩略图到对象存储
                           └─ 写回 images 表（name/mime/size/四个 path）
                                └─ 返回 { id(9位), urls }
```

**缩略图生成参数**
- 目标边长：128 / 256 / 512 px；
- 策略：**保持宽高比，最长边缩放到目标边长**（fit/contain），**不放大**（原图小于目标时保留原尺寸），**不裁切**；
- 格式：照片类（JPEG）转 WebP 可选；透明图（PNG）保留透明通道；处理库建议 `sharp`（Node）或 `ImageMagick`。

**关键保障**
- **先成后写**：原图 + 三档缩略图全部上传成功后才写库；任一步失败则回滚已上传 object，数据库不留脏记录。
- **原子写库**：单条 `INSERT` 完成，避免半初始化状态。

## 四、文件名与 ID 规则

**文件名（`name`）**
- 长度 1–20 字符（Unicode 码点计）；
- 字符集 `[\u4e00-\u9fa5A-Za-z0-9_]`；
- 允许重名（不建唯一约束），展示层用 `name + #id(9位)` 区分；
- 修改/上传无频率限制。

**ID（`id`）**
- `BIGINT` 自增（`BIGSERIAL`/`AUTO_INCREMENT`），首位 = 1；
- 展示零填充：`String(id).padStart(9, '0')` → `000000001`；
- 并发安全：自增序列原子分配，唯一且不回退。

## 五、边界情况处理

| 边界 | 处理 |
|---|---|
| 超出 10MB | 前端预检 + 后端拦截，提示「图片大小超过 10MB」 |
| 格式非法 | 扩展名 + MIME + 魔数三重校验，拒绝并提示 |
| 文件重名 | 允许（用 id 区分，object key 不冲突） |
| 缩略图生成失败 | 回滚本次上传（不留脏 object/脏记录），提示重试 |
| 非方图 / 超小图 | 缩略图保持比例、不放大，超小图原样保留 |
| 原图缺失（仅缩略图在） | 展示降级：优先原图，缺失则用最大可用档缩略图兜底 |
| ID 达 9 位上限 | 触发扩容评估（扩展位数 / 迁移方案） |
| 删除图片 | 按四个 object key 删除对象 + 删库记录 |

---

## 六、与账户功能的关联

- `owner_id` 关联账户体系的 `auth.uid()`，RLS 按 `owner_id` 隔离；
- `id` 与账户 `account_id` 同为「BIGINT 自增 + 9 位零填充」，规则统一；
- 头像功能可复用本方案：头像即一张走本表的图片（仅额外固定使用 128 档缩略图展示）。
