# 个人信息管家 · 用户体验评估与问题记录

- 评估日期：2026-10-14（v2.7.0，线上 Web 版 `personal-agent-08495.app.workbuddy.host`，bundle `index-CqCFoo0I.js`）
- 评估方式：真实浏览器（Edge headless + Playwright）以普通用户身份走查，辅以源码静态审查
- 覆盖流程：登录页交互 → 首页/全部信息 → 待办 → 思维树（新建树/多树/持久化）→ 回顾 → 工具箱 → 设置 → 回收站
- 证据截图：`qa/ux-shots/*.png`；原始数据：`qa/ux-shots/ux-report.json`、`mt-report.json`
- 说明：核心数据流程需登录（短信/微信），评估中采用本地注入测试会话；思维树为 localStorage 存储可完整实操，其余云端页面按「会话失效」状态实测（该状态本身即是真实用户会遇到的场景）

---

## 一、总体结论

产品整体观感整洁、信息架构清晰，v2.7.0 思维树林核心链路（新建树→多树共存→刷新恢复→树林入口→交叉建议引导）**全部走通**，此前修复的「新建树无反应」bug 已在线上验证生效。主要短板集中在：**会话失效处理缺失**、**手动建树功能闭环不完整**、**思维树数据仅存本机**三处。

## 二、问题清单（按优先级排序）

### 问题 1：会话过期后全局仅显示「操作失败，请稍后重试」，无重新登录引导

- **问题描述**：access token 失效时，首页、全部信息、待办、回顾、设置、回收站的所有请求返回 401，页面仅展示笼统的「操作失败，请稍后重试」（实测首页/记录/待办/设置/回收站全部命中），既不提示「登录已过期」，也不跳转登录页；用户会误以为软件故障，反复刷新无果。
- **影响程度**：高
- **改进建议**：在 `recordService`/cloud 调用层统一拦截 401 与「token 失效」错误：① 弹出「登录已过期」对话框；② 跳转登录页并通过 `navigate(from)` 在重登后回跳原页面；③ 错误文案按 401 / 网络中断 / 服务器错误三类区分展示。
- **优先级**：P0 —— token 过期是必现场景，影响全部核心功能的可用性与用户信任。
- **预期改进效果**：会话过期时用户一步完成重登并回到原操作现场；「软件坏了」类困惑与无效刷新基本消除。

### 问题 2：手动「新建树」得到的是功能死胡同——根节点无法手动添加第一个思考点

- **问题描述**：侧栏「新建树」创建的空树，根卡片只有「重新生成全部分支（AI）/ 删除整棵树 / 还原 / 手写板」（见 `mt-5-sidebar.png`）；「添加一个思考点」手输入口仅存在于子节点上。空树没有任何子节点，导致不调用 AI 就无法给新树添加第一条内容。
- **影响程度**：高
- **改进建议**：在根卡片补充与子节点一致的「添加第一个思考点」内联输入框（复用 `MindTreeNodeView` 现有 editing 交互），并把「还原」改为「撤销本次修改」或加 Tooltip 说明。
- **优先级**：P0 —— 这是 v2.7.0 主打功能的主路径闭环缺失；「不依赖 AI 手工建树」是合理且常见的使用方式。
- **预期改进效果**：新树创建后立即可手工录入内容，功能闭环完整；AI 弱网/不可用时建树流程不受阻。

### 问题 3：思维树数据仅存本机 localStorage，与「云端隔离存储」的产品承诺不一致

- **问题描述**：`personal-agent.mindforest.v1` 只写在浏览器本地（实测刷新后保留、结构正确：2 棵树/0 树林/0 交叉）。换设备、清浏览器缓存、Web 端与桌面端之间均不同步，一旦丢失无法恢复。
- **影响程度**：中
- **改进建议**：短期：设置页与思维树页提供「导出/导入 JSON」；中期：复用现有云库（新增 mind_trees 表或并入 settings），实现「本地缓存 + 登录后云端同步」。
- **优先级**：P1 —— 数据丢失是用户最不能容忍的问题；现有云库基础设施可复用，改造成本可控。
- **预期改进效果**：思维树跨设备一致、可恢复；「数据云端隔离存储」承诺对全部数据成立。

### 问题 4：错误提示同质化、缺少重试操作

- **问题描述**：绝大多数失败都渲染同一句「操作失败，请稍后重试」，且首页「最近记录」、回收站等处无重试按钮（思维树页有重试，行为不一致）。
- **影响程度**：中
- **改进建议**：抽取统一错误组件：错误分类文案 + 「重试」按钮 + （网络错误时）「检查网络」提示；全站页面统一接入。
- **优先级**：P1 —— 与问题 1 同根，可一次重构同时解决；成本低收益高。
- **预期改进效果**：瞬时故障用户可自行重试恢复，减少支持成本；错误可自助定位。

### 问题 5：根卡片「还原」按钮语义不明

- **问题描述**：根卡片右上「还原」无任何说明，用户无法预判会撤销什么（实测截图可见），误点可能丢失刚生成的分支。
- **影响程度**：中
- **改进建议**：改文案为「撤销本次修改」，点击前弹确认，或在按钮旁显示将被撤销的内容摘要。
- **优先级**：P2 —— 属可用性细节，但出现在核心功能首屏。
- **预期改进效果**：消除误操作与数据回退焦虑。

### 问题 6：登录页错误提示位置弱、验证码流程缺少帮助

- **问题描述**：错误文案统一渲染在卡片底部（距触发输入框远）；「获取验证码」60 秒倒计时内无「未收到验证码」帮助入口；表单校验本身良好（实测空号/错号即时提示「请输入正确的 11 位手机号」）。
- **影响程度**：低
- **改进建议**：错误提示内联到对应输入框下方；倒计时区补「收不到验证码？」折叠帮助；验证码输入框 `inputMode="numeric"` 便于手机键盘弹数字。
- **优先级**：P2 —— 登录是所有用户的第一个触点，细节值得打磨但非阻塞。
- **预期改进效果**：登录转化率与首次体验顺畅度提升。

### 问题 7：侧边导航可访问性不足

- **问题描述**：左导航「全部信息/想法/资料/待办/回顾/思维树/工具箱/回收站/设置」捕获均为无 role 的 `div`，键盘与读屏用户不可达（按钮类控件大多正常）。
- **影响程度**：低
- **改进建议**：导航项改用 MUI `ListItemButton`（组件库已引入）或补 `role="link"` + `tabindex` + 选中态 `aria-current`。
- **优先级**：P2 —— 影响特定用户群与无障碍合规。
- **预期改进效果**：键盘可完整导航，读屏可识别当前页面。

### 问题 8：设置页加载失败时仍展示本地默认值，易造成误保存

- **问题描述**：设置加载失败（如 401）时页面顶部有「操作失败」，但表单照常显示默认值且「保存设置」可用，用户可能把默认值覆盖到云端。
- **影响程度**：低
- **改进建议**：加载失败时禁用「保存设置」并提示「当前显示为默认值，加载成功后可编辑」。
- **优先级**：P2 —— 防御性细节。
- **预期改进效果**：避免失败状态下的脏数据写回。

### 问题 9：VS 路径设置占位符过时、缺少自动检测

- **问题描述**：占位符示例为 VS2022 路径，而本机实装 VS2026；该路径理论上可由 `vswhere` 自动检测（代码中已有 `locateClExe()` 能力）。
- **影响程度**：低
- **改进建议**：增加「自动检测」按钮一键填入；占位符改为「留空则自动检测」。
- **优先级**：P3 —— 桌面端小改进。
- **预期改进效果**：C++ 工具链配置零门槛。

### 问题 10：空数据首屏缺少上手引导

- **问题描述**：新用户首页所有计数为 0、最近记录为空时直接展示空区块，没有「记录第一条想法」「生成第一棵思维树」等引导动作。
- **影响程度**：低
- **改进建议**：各空状态卡内嵌 1 个主行动按钮（快速记录 / 去思维树），首页空态给出 3 步上手清单。
- **优先级**：P3 —— 提升新用户激活，不阻塞老用户。
- **预期改进效果**：新用户首次会话即可完成一次核心动作闭环。

## 三、实测验证通过的点（保持现状）

1. 新建树内联输入框（上次 `window.prompt` bug 修复）在线上正常工作，回车/对勾/取消交互完整；
2. 多树共存、树重命名/删除入口、树林「新建树林」入口（≥2 棵树时开放）均正常；
3. localStorage 持久化正确：刷新后 2 棵树完整保留，存储结构（trees/forests/crossLinks）符合设计；
4. 交叉关联空状态引导文案清晰（「请先在左侧选择或创建一个树林…」）；
5. 工具箱速查库离线可用、搜索/分类/复制齐全；「读取选区」对浏览器环境有明确提示；
6. 登录页手机号即时校验、未登录访问受控路由一律跳登录页；
7. 全站无 JS 运行时错误（pageerror 为 0）、无资源加载失败。
