## 二、问题清单

> 本期重点问题为「与上期对比」维度下的遗留项与新增观察点。已修复项不再重复列改进建议，统一在第三节「与上期对比」呈现。

### 问题 1：思维树数据仍仅存本机，无云端同步（上期问题 3 的遗留）

- **问题描述**：`personal-agent.mindforest.v1` 仍只写在浏览器 localStorage（`mindforest-store.ts` 的 `loadForestStore`/`saveForestStore` 均直接读写 localStorage，页面注释亦明示「思维树仅存本地，需手动搬运」）。已新增「导出 JSON / 导入 JSON」解决手动备份与迁移，但换设备、清浏览器缓存、Web 端与桌面端之间仍无法自动同步，一旦忘记手动导出即丢失且不可恢复。
- **影响程度**：中
- **改进建议**：中期复用现有云库，新增 `mind_trees` 表（或并入 `settings`），实现「本地缓存 + 登录后云端同步」；同步策略建议：登录后拉取云端版本做合并/覆盖提示，本地写入防抖后推送云端。导出/导入 JSON 保留作为离线兜底。
- **优先级**：P1 —— 数据丢失是用户最不能容忍的问题；现有云库基础设施可复用，改造成本可控，且这是「数据云端隔离存储」产品承诺对思维树的唯一缺口。
- **预期改进效果**：思维树跨设备一致、可恢复；「数据云端隔离存储」承诺对全部数据成立。

### 问题 2：会话失效拦截建议用「真实过期 token」补充验证

- **问题描述**：源码层面会话失效链路已完整（`main.tsx` 注册 `setUnwrapAuthHook(onServiceError)` → `unwrap` 抛错前回调 → `isAuthExpired` 识别 → `reportAuthExpired` 清会话跳登录 → `LoginPage` 消费回跳路径）。但本次评估注入的测试会话使用伪 token（`ux-eval-fake-token-not-real`），实测首页/记录/待办/设置/回收站命中 401 后页面仍显示「操作失败，请稍后重试」并**未触发跳转登录**。这可能是评估脚本伪 token 触发的 401 错误结构与真实 SDK 返回结构不一致所致，但存在「真实 token 过期场景拦截未生效」的回归风险，无法仅凭源码断言。
- **影响程度**：中（潜在）
- **改进建议**：补充一次「真实登录 → 手动使 token 失效（或等待过期）→ 刷新页面」的端到端验证，确认 `isAuthExpired` 能正确识别真实 SDK 的 401 结构并触发跳转；若未触发，则补齐对应错误字段到 `isAuthExpired` 的识别分支。
- **优先级**：P1 —— 会话失效是必现场景，是上期 P0 问题的修复验证，务必确认修复真实生效而非仅源码存在。
- **预期改进效果**：确认会话过期时用户一步完成重登并回到原操作现场，彻底消除「软件坏了」类困惑。

### 问题 3：回顾页初始加载失败静默无提示

- **问题描述**：本次走查中，首页/记录/待办/设置/回收站在会话失效时均展示「操作失败，请稍后重试 + 重试」；唯「回顾」页在同样 401 状态下仍正常展示「本周/本月/自定义/生成回顾」而无任何错误提示，直到用户点击「生成回顾」才可能失败。若回顾页在加载阶段确实拉取记录/分类数据，则失败被静默吞掉，用户无从得知。
- **影响程度**：低
- **改进建议**：核对回顾页是否在初始渲染时拉取数据；若有，统一接入与其余页面一致的「错误文案 + 重试」组件，保持全站失败态一致。
- **优先级**：P3 —— 属一致性细节，不阻塞核心功能，但影响全站错误处理的统一性。
- **预期改进效果**：全站失败态行为一致，用户可自助定位并重试。

### 问题 4：思维树「导出/导入」缺少数据覆盖风险提示强度

- **问题描述**：导入 JSON 的 Tooltip 已提示「会覆盖当前数据」，但未在导入前弹出二次确认对话框。用户误点导入（或选错文件）会直接清空现有树林，风险较高；且导入文件为任意 JSON 时依赖 `deserializeForestStore` 校验，校验失败虽会提示「导入失败」，但覆盖行为发生在校验通过之后，一旦选错合法但内容不同的备份文件即不可逆。
- **影响程度**：低
- **改进建议**：导入前弹出确认对话框，明确列出「将覆盖当前 N 棵树 / M 个树林」；导入成功后支持「撤销导入」或先自动备份当前数据到 localStorage 的 `backup` key（已有 `BACKUP_KEY` 机制可复用）。
- **优先级**：P3 —— 数据安全细节，配合问题 1 的云端同步落地前尤为必要。
- **预期改进效果**：避免误导入导致的数据覆盖丢失，提升数据安全感。
