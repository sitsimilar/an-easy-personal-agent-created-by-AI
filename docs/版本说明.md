# 个人信息管家 · 版本说明

> **当前版本：v2.12.1**

「个人信息管家」是一款帮你管理个人零散信息、把想法展开成结构化思考的个人智能助手。它由两部分组成：一个**网页应用**（云端存数据），加上一个**常驻桌面的伴侣程序**（悬浮窗 + 系统托盘）。

---

## 一、这个软件能做什么（通俗总览）

把它当成你的「个人第二大脑」+「随身的代码审查助手」：

- **随手记**：想法、资料、待办，想到就记。它会自动帮你分类、写摘要，并把相关内容关联起来。
- **找得快**：关键词一搜就出来；还能自动提炼长文重点、整理待办、生成阶段总结和后续行动建议。
- **思维树**：输入一个主题或待解决的问题，沿「核心概念 / 前提与假设 / 可行性与风险 / 反面观点 / 下一步行动」五个维度生成分支，任意思考点可继续深挖成多级树；支持多棵树共存、归入「思维树林」组群，AI 自动识别跨树相关内容并给出交叉建议；每个思考点可添加文字备注。
- **桌面常驻**：一个置顶小悬浮窗 + 系统托盘，随时唤出、用完自动收起。
- **工具百宝箱**：在线跑 JS、编译调试 C++、自然语言生成代码、C# 速查库、截图识别。

## 二、当前版本（v2.12.1）功能清单

### 本版修正（v2.12.1）：链接元数据抓取全量失败

v2.12.0 发布后，线上链接抓取对**所有真实站点**均返回 502。根因与修复如下：

- **域名目标全量 502（主因）**：服务端代理为防 DNS rebinding，用 `lookup` 钩子把连接钉在已校验 IP 上；但 Node ≥ 20 内部以 `{ all: true }` 调用该钩子，要求回调返回**数组**。原实现返回单值，导致目标只要是域名（而非 IP 字面量）就在建连前抛 `ERR_INVALID_IP_ADDRESS`。已改为兼容两种调用约定。
- **IPv6 优先导致超时**：双栈站点的 DNS 常把 AAAA 排在前面，而运行环境无 IPv6 出口，原实现取第一个地址会白等 5 秒。现改为 **IPv4 优先**排序，并在同一跳内**依次回退**候选地址（仅连接类错误换下一个；已收到响应则不重试，避免把 404 漂移成 502 或重复外呼），全部失败才报 502；所有尝试共用同一个 5 秒总预算。
- **代理出网支持**：新增零依赖代理探测（`HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`，大小写均识别）。HTTPS 目标先 `CONNECT` 到**已校验 IP** 再自行 TLS（`servername` 保留域名，DNS 钉扎不丢）；HTTP 目标走 absolute-form。响应新增 `viaProxy` 字段，线上可一眼确认实际出网路径（不暴露代理地址与凭据）。
- **测试盲区固化**：本次缺陷漏网是因为本地桩只用 `127.0.0.1` 这类 IP 字面量，`net` 会跳过 `lookup`/DNS 逻辑。已新增 `__setLookupForTest` 测试钩子与域名路径回归用例（含地址回退、404 语义不被污染、私网拦截护栏），并在 `qa/README.md` 写入硬规则「SSRF 本地桩禁止只用 IP 字面量」。测试总数 501，全部通过。

### 本版重点：P0 三项（系统提醒 / 循环待办 / 链接元数据）

- **系统级提醒**：待办到点弹出系统通知（桌面端 Windows 通知中心 / Web 浏览器通知），点击通知前置窗口并直接打开对应记录；设置页新增「提醒」卡片，可配置总开关、提前量（0/5/10/15/30/60 分钟）与免打扰时段（支持跨零点，结束后补发一次，超过 12 小时不再补）。同一记录的同一次提醒只弹一次。
- **循环待办**：新建/编辑待办可设「每天 / 每周（多选周几）/ 每月」循环，支持间隔、结束日期；完成一次自动生成下一期，原记录留档；每月固定日期在短月自动取月末，之后回到锚定日（如 31 日：1/31 → 2/28 → 3/31）。双击/重试只生成一条。
- **链接元数据**：资料类记录保存链接后自动抓取网页标题、描述、封面与域名并回填，标题为空时才用网页标题补全；抓取失败不阻塞保存，详情可手动重试。服务端代理做了 SSRF 防护（拒绝内网/回环/链路本地地址、非 80/443 端口、逐跳复验重定向）、5 秒超时、512KB 上限与 30 次/分钟限流。
- **数据迁移**：`records` 新增 recurrence / recurrence_parent_id / recurrence_next_id / link_meta；`settings` 新增 remind_lead_minutes / quiet_hours_enabled / quiet_start / quiet_end。全部可空或有默认值，旧数据无需回填，回退代码即可回滚。

## 三、版本号与安装包命名规则

- 版本号采用「主版本 . 次版本 . 修订号」格式，统一写在项目各 `package.json` 的 `version` 字段里。
- **安装包一律按当前版本号命名**：
  | 类型  | 命名格式                     | 当前版本（v2.11.0）             |
  | --- | ------------------------ | ------------------------ |
  | 安装版 | `个人信息管家 Setup {版本号}.exe` | `个人信息管家 Setup 2.11.0.exe` |
- 以后每次发版，只需递增 `version` 字段（例如 `2.8.0 → 2.8.1`），安装包名称会自动带上新版本号，无需手动改文件名。
