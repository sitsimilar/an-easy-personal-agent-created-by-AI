# 个人信息管家 · P0 增量 PRD（2026-10）

版本基线 2.11.0｜范围：仅 3 项 P0（系统级提醒 / 待办循环 / 链接元数据）｜不做市场调研

## 1. 背景与目标

现有提醒只表现为待办列表上的时间文字，到点无任何系统通知，用户必须自己盯屏；习惯类待办完成后要手工重建，链路断裂；链接资料入库后只有一串 URL，看不出是什么、也看不到封面。

本期目标（三项已既定，不扩范围）：
1. 待办提醒到点即弹系统通知（桌面原生 / 浏览器），点击直达该记录，且能配置开关、提前量、免打扰。
2. 待办支持日/周/月循环，完成后自动续上下一期，原记录留档可追溯。
3. 新建链接类资料自动回填 OG 标题/描述/封面/域名，失败降级不阻塞保存，且服务端代理必须过 SSRF 防护。

## 2. 用户故事

P0-A：作为每天靠待办驱动的人，我希望到点手机/电脑弹系统通知，这样我不必盯着应用页面；作为被打扰敏感的人，我希望设置免打扰时段，夜间提醒不吵我；作为多端用户，我希望点通知就直接打开那条记录，而不是只看到一句"你有个待办"。

P0-B：作为养成习惯的人，我希望设"每天/每周一三五/每月 1 号"的循环待办，完成一次就自动出现下一期，不用手工重建；作为回顾者，我希望历史每一次完成都留痕，能看到"这条循环从哪天开始、完成过几次"。

P0-C：作为资料收集者，我希望贴个链接就能看到网页标题和封面，一眼认出是什么；作为整理者，我希望标题空着时自动用网页标题补上，抓不到也不影响我保存。

## 3. 功能范围

### P0-A 系统级提醒

用户可见行为：
- 设置页新增"提醒"卡片：总开关（复用已有 notify_enabled）、提前量（下拉 0/5/10/15/30/60 分钟，默认 0）、免打扰开关 + 起止时间（默认 22:00–08:00，关闭态）。
- 待办到"提醒时刻 = remind_at − 提前量"时弹通知：标题=记录标题（空则"待办提醒"），正文=分类/优先级 + 提醒时间；桌面端走 Electron 原生 Notification，Web 端走浏览器 Notification（首次开启总开关时请求权限）。
- 点通知：窗口前置（桌面端从托盘/最小化恢复）并打开该记录详情；记录已删除/不存在则进待办页并提示"该记录已删除"。
- 去重：同一条记录的同一次 remind_at 只弹一次，刷新/重启不重复。
- 免打扰：命中时段内不弹系统通知，改为时段结束后的第一个调度周期内补发一次；超过 12 小时未弹的直接丢弃（不堆积轰炸）。
- 调度器放渲染层（主进程无登录态）；窗口隐藏到托盘时仍必须生效（渲染定时器不得被后台节流降频）。

### P0-B 待办循环任务

用户可见行为：
- 待办新建/编辑弹窗新增"重复"：不重复（默认）/每天/每周/每月；间隔 1–99（默认 1）；每周可多选周几（默认取 remind_at 的星期，无 remind_at 则取今天对应星期）；可设结束日期（默认空=无限）。
- 完成一条带循环的待办：原记录置 done 并留在"已完成"区；自动生成 1 条新待办（pending），复制标题/内容/优先级/分类/标签/URL，remind_at 按规则推进（保留原时分；原 remind_at 为空则新记录也为空）。新记录与根记录共享循环规则，并记录父级以便追溯。
- 下一期超过结束日期：不生成，完成后提示"循环已结束"。
- 列表展示：卡片与详情显示循环标识（如"每天"、"每周一、三"、"每月最后一天"），循环链条在详情中可看到"由第 N 期生成"。
- 取消完成（done→pending）不回收已生成的下一期，仅提示"下一期已生成，可自行删除"。
- 规则计算为纯函数，供单测覆盖（qa/ 目录，node:test + esbuild 现有链路）。

### P0-C 链接元数据增强

用户可见行为：
- 资料类记录填了 http(s) 链接并保存后，后台异步抓取 OG 信息（标题/描述/封面/域名），回填到该记录；保存动作立即返回，不等待抓取（目标 < 1s）。
- 标题为空时用抓取标题回填；用户已填标题不覆盖。卡片与详情展示封面（16:9 裁切）与域名角标；封面加载失败时隐藏图片、不占位错乱。
- 抓取失败（超时/非 HTML/404/被拒）不报错打断，记录照常保存；详情显示"未能抓取网页信息 + 重试"。
- 历史已有链接记录不自动重抓（避免批量外呼），仅用户点击"重新抓取"时抓。
- 代理端点：`server.js` 新增纯 Node（零第三方依赖）`POST /api/link-preview`，请求体 `{"url":"…"}`；`GET /api/link-preview?url=…` 保留用于本地开发兼容。生产环境因腾讯云 WAF 会拦截查询参数中的 URL，前端固定走 POST。仅返回结构化 JSON，永不返回原始 HTML；限流 30 次/分钟/实例。开发态无该端点时前端直接降级，不阻塞开发。

## 4. 验收标准

P0-A（系统级提醒）
1. A1 开启总开关、提前量 0，创建"3 分钟后提醒"的待办 → 到点 ±60s 内出现系统通知（桌面端为 Windows 通知中心条目，Web 端为浏览器通知），标题等于记录标题。
2. A2 点击通知 → 应用窗口前置且自动打开该记录详情；记录已软删除时进待办页并提示"该记录已删除"。
3. A3 提前量 10 分钟：remind_at=10:00 的待办在 09:50±60s 触发；改回 0 后在 10:00±60s 触发。
4. A4 同一 (记录, remind_at) 只弹一次：触发后刷新页面、重启应用均不再弹；把 remind_at 改为新时间后允许再弹一次。
5. A5 免打扰 22:00–08:00（跨零点）：23:00 与次日 07:30 的提醒均不在该时段弹通知，且都在 08:00–08:05 补发一次；关闭免打扰后同样两条即时弹出。超过 12h 未补发的不再补。
6. A6 关闭总开关后不弹任何系统通知（列表仍显示提醒时间）；桌面端主窗口关闭到托盘（隐藏）状态下 A1 仍成立；Web 端 Notification 权限被拒时降级为应用内提示条，不报错、不阻塞其他功能。

P0-B（循环任务）
1. B1 "每天"循环待办完成后：原记录为 done 且仍在列表，新增恰好 1 条 pending 记录，标题/内容/优先级/分类/标签一致，remind_at = 原 remind_at + 1 天（时分不变）。
2. B2 "每周"选周一、周三：周一完成 → 下一期周三；周三完成 → 下一期下周一（跨周边界正确）。
3. B3 "每月"31 日：在 2 月/4 月等无 31 日的月份，下一期取该月最后一天；间隔设为 2 时同样按"每两月"推进。
4. B4 结束日期 2026-12-31：计算出的下一期等于该日仍生成；超过该日则不生成，完成时提示"循环已结束"，记录数不再增加。
5. B5 幂等：对同一条已完成记录重复触发完成（快速双击/接口重试）只产生 1 条新记录，不产生重复待办。
6. B6 兼容：不带循环的旧待办完成后仅置 done，与 2.11.0 行为一致；待办列表、日历、首页统计的条数除新增循环记录外无变化。

P0-C（链接元数据）
1. C1 新建资料填 https://github.com/xxx 并保存：保存 ≤1s 成功返回，随后卡片出现封面、域名 github.com；标题留空时自动填为抓取标题，已填标题不被覆盖。
2. C2 抓取失败降级：目标返回 404 / 5s 超时 / 非 HTML（如直接指向 .pdf）时，保存不失败，卡片无封面但显示域名，详情可点"重新抓取"。
3. C3 SSRF：代理对 127.0.0.1、localhost、192.168.1.1、[::1]、169.254.169.254、file://、非 80/443 端口一律拒绝（4xx + 中文原因），前端降级为无元数据；重定向到内网同样被拒。
4. C4 限制生效：代理 5s 超时返回 504、响应体 >512KB 或 content-type 非 text/html 返回错误码，前端均在 6s 内完成降级、不出现永久 loading。
5. C5 只读展示安全：封面仅当 URL 为 http(s) 时渲染，加载失败自动隐藏且不撑破卡片布局；点击链接新窗口打开且带 noreferrer。
6. C6 历史数据：升级后打开既有链接记录不发起任何外部抓取请求（可用网络面板确认），仅手动重试才请求。

## 5. 数据与兼容性要求

新增字段（写入 docs/db-setup.sql 的"增量迁移"段，线上手工执行 DDL；应用代码不执行 DDL）：
- records 增量：recurrence（JSONB，默认 null；结构含 freq=daily/weekly/monthly、interval、weekdays、endDate）、recurrence_parent_id（BIGINT，默认 null，根记录为空）、recurrence_next_id（BIGINT，默认 null，用于幂等）、link_meta（JSONB，默认 null；含 title/description/image/site/fetchedAt/status=ok|failed）。
- settings 增量：remind_lead_minutes（INT 默认 0）、quiet_hours_enabled（BOOL 默认 false）、quiet_start（TEXT 默认 '22:00'）、quiet_end（TEXT 默认 '08:00'）；总开关复用已有 notify_enabled。
- 新增索引：records(owner_id, todo_status, remind_at) 支撑提醒轮询；records(owner_id, recurrence_next_id) 可选。
- 类型同步三处：shared/types/domain.ts（InfoRecord/RecordCreateInput/UserSettings）、web/src/lib/database.types.ts（RecordsRow/SettingsRow）、web/src/services/recordService.ts 的映射与 toSnake。
- 旧数据默认值：所有新列可空、读取缺失按 null 处理，旧待办=无循环、旧链接=无元数据、旧设置=提前量 0 + 免打扰关闭，行为与 2.11.0 一致。
- 查询兼容：列表/搜索/统计不按新列过滤（避免漏数）；循环待办生成后正常进入现有查询。
- 回滚：新列全部可空，回退代码后不受影响；已生成的循环记录退化为普通待办（不再续期），link_meta 不再展示但数据保留，无需数据清理。
- 状态一致性：循环生成与幂等依赖 recurrence_next_id 落库，需保证"先置 done + 生成新记录 + 回写 next_id"顺序，任一步失败给出可重试的中文提示，不产生半成品（新记录生成失败则允许用户手动重新完成）。

## 6. 非目标（本期不做）

- 邮件 / 企微 / 短信 / 移动端推送通道，以及任何需要外部账号或证书的通道。
- CalDAV / 系统日历双向同步、循环事件在日历视图展开为多期实例。
- 链接失效批量巡检、死链告警、封面图本地化存储或 CDN 转存、AI 生成封面。
- 提醒的贪睡/稍后提醒、按记录自定义免打扰、提醒历史中心页。
- 循环规则的高级形态（按星期序数、按工作日、跨时区规则）。
- 新增第三方依赖（代理与解析必须零依赖；循环规则不得引入日期库）。

## 7. 待确认问题（含默认假设，可直接开工）

1. 应用完全退出（托盘"退出"）后是否仍需弹提醒？默认：否，仅进程存活（含隐藏到托盘）时生效；退出后下次启动补发 12 小时内未弹过的提醒。
2. 循环待办是否需要在日历视图按周期展开显示？默认：本期不展开，日历仍按创建日期展示；循环标识仅在待办列表/详情出现。
3. 链接抓取是否可占用现有 AI 调用能力（如用它生成描述）？默认：不占用，只用 server.js 纯 Node 代理解析 OG，失败即降级，不调用 LLM。
