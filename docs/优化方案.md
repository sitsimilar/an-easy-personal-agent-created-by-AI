# 个人信息管家 · 40 项优化方案（v2.9.3）

> 依据 `docs/全面审查报告.md` 的 40 项问题，按原顺序逐条给出「改进建议 → 可执行方案 → 优化原因 → 预期效果」，作为统一执行的实施规格。
> 关键决策已前置明确：**P0 VS 链路「打通」（保留功能接线）**；**「开启通知」无后端 → 移除**；**「启用桌面悬浮窗」→ 接入**。

---

### 1. [P0] VS 代码分析链路「断头路」
- **改进建议**：打通「VS 启动 → 读码 → LLM 分析 → 悬浮窗推送」完整链路，而非删除功能。
- **可执行方案**：在 `web/src/components/CompanionPanel.tsx` 订阅 `bridge.onVsStarted`；收到 changedFiles 后调 `aiService` 分析（复用 `analyzeCode` 或新增 `analyzeChangedFiles`），成功后 `bridge.analysisDone({...})` 回传，失败也回传错误以复位 `analyzing`；同时确认 `ipc.ts` 的 `evtVsStarted`/`analysisDone` 契约两侧一致。
- **优化原因**：核心卖点当前不工作，且半成品管线误导用户与维护者。
- **预期效果**：VS 启动后自动读码、分析、推送建议，悬浮窗状态正确收尾。

### 2. [P1] IPC 边界无来源/入参校验（安全）
- **改进建议**：为特权 handler 增加「来源校验 + 入参白名单 + 路径沙箱」。
- **可执行方案**：`desktop/src/main/ipc.ts` 中 `cppRun/cppDebugStart` 的 `binaryPath/sourcePath` 强制解析并校验位于 `CPP_TMP_DIR` 内；`cppCompile` 源文本加长度上限（如 1MB）；`setExportDir` 加长度/非法字符校验；`readSelection` 改为仅快捷键触发（不经 renderer 任意拉取）；统一校验 `event.sender` 属于主窗口/悬浮窗。
- **优化原因**：远程 Web 一旦被 XSS 可触发本地任意执行/剪贴板读取/磁盘枚举。
- **预期效果**：恶意或异常输入无法越权执行本地命令，攻击面大幅收敛。

### 3. [P1] 悬浮窗 suspend/resume 配对缺陷
- **改进建议**：保证 suspend 的所有出口都能 resume。
- **可执行方案**：`desktop/src/main/analysis-orchestrator.ts:95-143` 将 `suspendFloatingAutoCollapse()` 移到确认进入分析之后；或将整段包进 `try/finally`，`finally` 中 `resumeFloatingAutoCollapse()`。
- **优化原因**：多条提前 return/抛错分支漏掉 resume，导致自动收起永久失效。
- **预期效果**：任何路径下自动收起都不会被「卡住」停用。

### 4. [P1] VS 探测每 3s 反复 spawn PowerShell + Add-Type 重编译
- **改进建议**：缓存编译结果 + 退避探测频率 + 节流。
- **可执行方案**：`desktop/src/main/vs-monitor.ts` 中 `detectForegroundPid` 的 `Add-Type` 结果缓存复用（首次编译后复用类型）；VS 未运行时 poll 退避到 10~15s；`detectForegroundPid` 结果做 1~2s 节流。
- **优化原因**：每 3s 一次 powershell spawn + 每次重编译 C#，长期占用主进程 CPU/进程创建。
- **预期效果**：常驻运行时主进程 CPU 开销显著下降，无黑窗风险。

### 5. [P1] 搜索结果「清除搜索」按钮无效
- **改进建议**：用 React Router 受控方式清空关键词。
- **可执行方案**：`web/src/pages/RecordsPage.tsx:79-88` 把 `window.history.replaceState` 改为 `setSearchParams` 删除 keyword，或直接 `setFilter({ keyword: undefined, page: 1 })` 触发 reload。
- **优化原因**：replaceState 不触发 useSearchParams 更新，页面不重渲染。
- **预期效果**：点击「清除搜索」立即恢复完整列表。

### 6. [P1] 详情弹窗「重新生成摘要」后不刷新
- **改进建议**：让重新生成的结果回写当前详情态。
- **可执行方案**：`web/src/components/RecordDetail.tsx` 的 regenerateSummary 成功后，用返回的 InfoRecord 更新本地 record state（或父级 detail state），而非仅 onChanged 刷新列表。
- **优化原因**：摘要更新只刷新列表、不更新详情对象，弹窗显示旧摘要。
- **预期效果**：重新生成后弹窗即时展示新摘要。

### 7. [P1] 详情弹窗「相关记录」点不动
- **改进建议**：接通关联记录跳转。
- **可执行方案**：`web/src/components/RecordDetail.tsx:262` 给 `<RelatedRecords>` 传 `onSelect`，点击后打开目标记录（替换当前 record）。
- **优化原因**：「智能关联」只展示不可跳转，功能做了一半。
- **预期效果**：形成「记录 ↔ 相关记录」双向浏览闭环。

### 8. [P1] 启动等待界面无超时兜底
- **改进建议**：给 bootstrap 加超时与重试。
- **可执行方案**：`web/src/main.tsx` 的 bootstrap 加 10s 超时；`web/src/components/BootScreen.tsx` 增加超时态 + 「重试」按钮（重新触发 bootstrap）+ 可读错误文案。
- **优化原因**：网络/会话卡住时「正在加载…」永不结束。
- **预期效果**：启动卡死时有明确反馈与自救入口。

### 9. [P1] 昵称/头像只在设置页生效，顶栏未同步
- **改进建议**：全局统一读昵称/头像。

- **优化原因**：v2.9.x 昵称/头像是「半成品」，改完全局不可见。
- **预期效果**：设置昵称/头像后顶栏即时全局生效。

### 10. [P2] 顶栏「导出」仅当前页 + Layout 订阅 records 重渲染
- **改进建议**：导出全量 + 移除组件级 records 订阅。

### 11. [P2] 检索 keyword 未转义 → PostgREST 过滤器注入
- **改进建议**：转义特殊字符或改参数化。
- **可执行方案**：`web/src/services/recordService.ts:124,198,308` 对 kw 转义 `%/_/\,()"`（`replace(/[%_\\,()"]/g, '\\$&')`）或改用 SDK 参数化 `ilike` 分列组合。
- **优化原因**：用户输入含 `,()%_` 可注入额外过滤条件或致查询报错。
- **预期效果**：任意关键词都不会破坏查询语义，杜绝过滤注入。

### 12. [P2] 图片对象一致性（孤儿对象 / 脏记录）
- **改进建议**：上传失败删对象、删除先删库。

- **优化原因**：上传中途失败泄漏对象；删除失败留脏记录（死图）。
- **预期效果**：不残留孤儿对象与死图记录，存储与库一致。
