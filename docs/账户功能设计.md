## 〇、关键决策定稿（含出处说明）

| 决策点      | 定稿                              | 说明                                                            |
| -------- | ------------------------------- | ------------------------------------------------------------- |
| 头像大小     | **单张 ≤ 5 MB**                   | 你原提「无上限」；此处按行业建议设 5MB 上限（防恶意大文件、控存储成本）。如坚持无上限可改为不限，仅保留服务端超时兜底 |
| 头像压缩     | **保留原图 + 生成 128/256/512 三档缩略图** | 原图不压缩画质（满足你的「不压缩」诉求），展示统一走缩略图（保证加载性能）                         |
| 头像格式     | JPEG / PNG / WebP               | 双端校验（扩展名 + MIME + 魔数）                                         |
| 昵称唯一性    | **允许重名，不建唯一约束**                 | 用 `account_id` 区分用户；重名时展示层以「昵称 + #ID」辅助辨识                     |
| 昵称长度/字符集 | 1–20 字符；中英文、数字、下划线              | 按你的要求                                                         |
| 昵称修改频率   | 1–20 字符；中英文、数字、下划线              | 按你的要求                                                         |
| 账户 ID    | **BIGINT 自增 + 展示零填充为 9 位**      | 数值存储性能/排序最优，展示为 `000000001`                                   |

## 一、数据表：`user_profiles`

> 用户认证主体仍由云服务 `auth.users` 管理；本表存放「资料类」扩展字段，`owner_id` 关联 `auth.uid()`，RLS 按 `owner_id` 隔离。

| 字段名          | 类型            | 长度     | 可空 | 默认值     | 索引                           |
| ------------ | ------------- | ------ | -- | ------- | ---------------------------- |
| `owner_id`   | `uuid`        | —      | 否  | —       | `PRIMARY KEY`（关联 auth.uid()） |
| `account_id` | `BIGINT`      | —      | 否  | 自增      | `UNIQUE`（全局唯一，不可修改）          |
| `nickname`   | `VARCHAR`     | 20（字符） | 是  | `NULL`  | 无（允许重名）                      |
| `avatar_url` | `TEXT`        | —      | 是  | `NULL`  | 无                            |
| `avatar_key` | `TEXT`        | —      | 是  | `NULL`  | 无（对象存储 object key，用于删除）      |
| `created_at` | `TIMESTAMPTZ` | —      | 否  | `now()` | 无                            |
| `updated_at` | `TIMESTAMPTZ` | —      | 否  | `now()` | 无                            |

## 二、头像功能

### 1. 流程

- **上传/修改**：前端预检（格式/大小）→ 上传对象存储 → 拿到 `avatar_url` + `avatar_key` → 写回本表 → **先成后换**（新图上传成功后再原子更新 URL，最后删旧 object）。
- **删除**：清空 `avatar_url`/`avatar_key` + 删 object → 回落默认头像。

### 2. 展示规格

| 场景         | 尺寸                    | 说明                       |
| ---------- | --------------------- | ------------------------ |
| 个人主页 / 设置页 | 128×128（大图档可 256×256） | 圆形裁切 `border-radius:50%` |
| 列表 / 关联    | 32×32 或 40×40         | 圆形                       |
| 评论         | 40×40 或 48×48         | 圆形                       |

统一 `object-fit:cover` 防止非方图变形。

### 3. 异常处理

| 异常     | 处理                                                |
| ------ | ------------------------------------------------- |
| 格式非法   | 前后端双重校验（扩展名 + MIME + 魔数），拒绝并提示「仅支持 JPEG/PNG/WebP」 |
| 超出 5MB | 前端预检 + 后端拦截（业务错误码），提示「图片大小超过 5MB」                 |
| 上传失败   | 保留原头像不变，提示重试                                      |

### 4. 删除后默认展示

默认头像 = **昵称首字 + 品牌色底**（未设置昵称则用账户 ID 末位映射品牌色）；未登录/无数据时用灰色人形占位图。

## 三、昵称

| 规则   | 定义                                       |
| ---- | ---------------------------------------- |
| 长度   | 1–20 字符（Unicode 码点计，1 中文 = 1 字符）         |
| 字符集  | `[\u4e00-\u9fa5A-Za-z0-9_]`              |
| 空值   | 禁止（长度 ≥1）                                |
| 非法字符 | 拒绝并提示「仅支持中英文、数字、下划线」                     |
| 重复   | 允许（不建唯一约束），展示层用「昵称 + #ID」区分              |
| 敏感词  | 敏感词库 + 规则匹配，命中替换为 `*` 或拒绝；后端二次校验 + 高危词复审 |
| 修改频率 | 无限制                                      |

---

## 四、唯一账户 ID

| 项    | 定稿                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------ |
| 字段类型 | `BIGINT`（数值存储）                                                                                         |
| 生成方式 | 数据库 `BIGSERIAL`/`AUTO_INCREMENT` 自增，首位用户 = 1                                                           |
| 展示格式 | 零填充为 9 位字符串 `000000001`（`String(id).padStart(9,'0')`）                                                  |
| 唯一性  | `UNIQUE` 索引；自增序列在并发下原子分配，保证唯一且不回退                                                                      |
| 不可修改 | 写入后禁止更新（业务层 + 触发器/权限双重保障）                                                                              |
| 后台查看 | 只读接口：`SELECT account_id, nickname, phone(脱敏), avatar_url, created_at ORDER BY account_id`，支持分页与按 ID 检索 |

## 五、校验规则汇总

| 字段           | 规则                        |
| ------------ | ------------------------- |
| `account_id` | 自增唯一、不可空、不可修改             |
| `nickname`   | 1–20 字符、字符集白名单、敏感词过滤、允许重名 |
| `avatar_url` | 仅存 URL，格式由上传链路保证          |

## 六、边界情况汇总

| 边界                 | 处理                |
| ------------------ | ----------------- |
| 头像上传超时/断网          | 原头像不变，可重试         |
| 删除头像               | 回落「首字/品牌色」默认头像    |
| 昵称全空格              | 视为空，拒绝            |
| 昵称含 emoji/特殊符号     | 不在白名单内，拒绝         |
| 账户 ID 达 9 位上限（10⁹） | 触发扩容评估（扩展位数或迁移方案） |
| 并发注册               | 自增序列保证 ID 唯一，无冲突  |

## 七、落地映射（个人信息管家现状）

- `auth.users`（云服务 SDK 管理）负责登录凭证（手机号/微信）。
- 资料字段落地在 `settings` 表（每用户一行，`owner_id` 唯一）：
  - **唯一账户 ID** = `settings.id`（BIGINT 自增主键，全局唯一、不可修改），展示层零填充 9 位；
  - **昵称** = `settings.nickname`（VARCHAR(20)，可空，允许重名）；
  - **头像** = `settings.avatar_image_id`（指向 `images` 表）——沿用现有图片存储链路。
- 相较本设计初稿的独立 `user_profiles` 表，实际采用「复用 settings 单行」方案：避免头像字段跨表重复，
  且 settings 已是每用户一行 + `owner_id` 唯一，`id` 天然就是全局自增账户序列。
- 头像上传复用现有 `imageService`（对象存储 + 三档缩略图）；敏感词过滤目前为前端第一道过滤，
  线上二次校验与高危词复审需服务端能力配合。
- RLS：所有读写按 `owner_id = auth.uid()` 隔离（settings 已启用）。
